# Проверка алгоритма вне игры

Здесь лежит стенд, на котором проверяется самая ответственная часть мода — планировщик
раскладки. Он собирается из **настоящего кода мода** (`../src/ChestSorter/*.cs`) и заглушек
игровых классов, поэтому проверяет именно ту логику, которая работает в игре.

Что проверяется на каждом сценарии:

* план вообще строится;
* ни один сундук не переполнен;
* размещены все стопки до единой;
* **ни один предмет не потерян и не появился из ниоткуда**;
* ни одна стопка не превышает свой максимум;
* уникальные вещи (зачарованные, именные, рюкзаки) остались поштучно и не слились со стопками.

Сценарии включают худший случай: сундуки, забитые **уникальными** предметами под завязку —
ноль свободных ячеек и нечего объединять.

## Запуск

Нужен любой компилятор C# (`mcs`/`csc`) и среда выполнения:

```bash
mcs -target:exe -langversion:Latest -nowarn:0169,0414,0067,0649,0108,0114 \
    -out:test.exe Stubs.cs StubsGame.cs TestHarness.cs ../src/ChestSorter/*.cs
mono test.exe
```

Заглушки описывают ожидаемый вид игрового API и не являются его копией: они нужны,
чтобы алгоритм можно было гонять без игры.
