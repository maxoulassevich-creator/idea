# ТЗ. Часть 2 — Функциональная спецификация

**Версия:** 0.1 · **Статус:** черновик для согласования, код не пишется
**Связанные документы:** `TZ-01-architecture.md` (v0.2), `TZ-03-components.md` (планируется)

Документ описывает наблюдаемое поведение продукта. Технические механизмы — в части 1.

## 1. Роли и что они делают

| Роль | Может | Не может |
|---|---|---|
| **Ученик** | Проходить курсы, сдавать тесты и работы, видеть отзывы, прогресс, достижения, сертификаты | Видеть чужие работы, оценки, персональные данные других учеников |
| **Куратор** | Проверять работы своих групп, возвращать на доработку, писать отзывы, видеть прогресс своих учеников | Редактировать контент, менять зачисления, видеть чужие группы |
| **Преподаватель** | Всё, что куратор, по своим курсам; редактировать свои курсы; видеть отчёты по своим курсам | Управлять чужими курсами, настройками, лицензией |
| **Автор** | Создавать и редактировать свои курсы, программу, тесты, задания, рубрики | Проверять чужие работы, менять зачисления вне своих курсов |
| **Администратор** | Всё | — |

Роль назначается на уровне сайта, права на конкретный объект уточняются политикой (часть 1, §4.3). Один человек может быть преподавателем одного курса и учеником другого.

## 2. Курсы и программа

### 2.1. Структура

Курс → разделы → элементы. Элемент — урок, тест или задание. Вложенность разделов: один уровень в первой версии.

Каждый элемент имеет признаки:
- **обязательный** — влияет на завершение курса и выдачу сертификата;
- **оцениваемый** — даёт баллы в итоговый результат.

### 2.2. Типы контента урока

Текст (редактор блоков) · видео (загруженное, YouTube, VK Видео, Rutube, Kinescope, произвольный embed) · аудио · вложенные файлы · внешний embed · комбинация перечисленного в одном уроке.

Для видео фиксируется позиция просмотра; урок может требовать просмотра заданной доли для отметки о завершении.

### 2.3. Завершение урока

Настраивается на уровне курса, переопределяется на уровне урока:

| Правило | Поведение |
|---|---|
| Вручную | Ученик нажимает «Завершить» |
| По просмотру | Автоматически при достижении заданной доли видео |
| По времени | Не раньше заданного числа минут на странице |
| По вложенному тесту | Урок завершается вместе со сдачей теста |

### 2.4. Капельная выдача и предусловия

Капельная выдача: по дате · через N дней после начала обучения · после завершения указанного элемента · по дате начала потока.

Предусловия: завершение указанных элементов · прохождение теста с заданным баллом · принятие указанной работы.

**Правило: капельная выдача и предусловия применяются через логическое И.** Элемент доступен, только когда выполнены оба набора условий.

**Интерфейс показывает все причины блокировки сразу**, а не первую попавшуюся: «Откроется 14 марта» и «Требуется сдать работу «Практика 2»» выводятся вместе. Ученик должен понимать полную картину, а не открывать её по одной причине за раз.

### 2.5. Версии программы

Публикация изменений структуры создаёт новую версию программы. Уже выданные оценки и попытки продолжают ссылаться на версию, действовавшую на момент их создания. Ученики, находящиеся в процессе обучения, переходят на новую версию с пересчётом прогресса; о существенных изменениях (добавление обязательных элементов) администратор предупреждается до публикации.

## 3. Зачисление и доступ

### 3.1. Основания доступа

Доступ к курсу существует, пока активно хотя бы одно основание. Основания создаются: вручную администратором, покупкой в WooCommerce, активацией приглашения, импортом, через API, массовым зачислением.

Одновременно может действовать несколько оснований — например, покупка комплекта и отдельная покупка того же курса. Отзыв одного не отменяет доступ, пока действует другое.

### 3.2. Циклы обучения

Ученик может проходить курс повторно — в новом потоке или после истечения доступа. Каждое прохождение — отдельный цикл со своим прогрессом, попытками и работами. История предыдущих циклов сохраняется и доступна ученику и преподавателю.

Новый цикл создаётся: при зачислении в новый поток · при повторной покупке с политикой «новый цикл» · вручную администратором.

### 3.3. Срок доступа

Бессрочно · N дней от начала · до фиксированной даты · до окончания потока.

**Поведение при истечении:**

- прогресс, попытки и работы **сохраняются полностью**;
- закрытый контент блокируется, ученик видит сообщение о необходимости продления;
- уже полученные отзывы и результаты остаются доступны для чтения;
- **сертификат от нормального истечения доступа не отзывается**;
- при продлении обучение продолжается с той же точки, прогресс не обнуляется.

### 3.4. Заморозка

Администратор может приостановить обучение (болезнь, академический отпуск) с автоматическим продлением срока на длительность паузы. Во время паузы контент недоступен, дедлайны не идут, напоминания не отправляются.

### 3.5. Приглашения

Ссылка с кодом даёт доступ к курсу, комплекту или потоку. Настраивается: число активаций, срок действия ссылки, длительность выдаваемого доступа, целевая группа. Приглашение отзывается в любой момент; уже выданные основания при отзыве ссылки сохраняются, если не указано иное.

Журнал активаций доступен администратору: кто, когда, с какого адреса.

## 4. Коммерция

### 4.1. Принцип

**Собственной кассы нет и не будет.** Единственный путь платной продажи — WooCommerce. Это означает, что любой платёжный шлюз, работающий с WooCommerce, работает с курсами без нашего участия.

Бесплатные курсы работают без WooCommerce вообще — модуль можно не включать.

### 4.2. Связь товара и курса

Один товар может открывать: один курс · комплект курсов · доступ в поток. Вариации товара могут давать разный срок доступа или разный поток.

Настраивается на уровне связи:
- какие статусы заказа считать основанием для выдачи доступа (список, а не одно значение);
- какие статусы считать основанием для отзыва;
- длительность доступа;
- поток, в который зачислять;
- политика повторной покупки: продлить действующее основание · создать новое основание · создать новый цикл обучения.

### 4.3. Частичный возврат

**Основания доступа создаются по строкам заказа.** Возврат конкретной строки отзывает только основания, порождённые этой строкой. Другое активное основание сохраняет доступ.

Возврат суммы без указания товара (частичный возврат денег по заказу целиком) **не отзывает доступ автоматически** — операция попадает в очередь ручной проверки с уведомлением администратора. Автоматическое лишение доступа по неоднозначному сигналу недопустимо.

### 4.4. Диагностика зачисления

Отдельный экран показывает журнал `заказ → пользователь → курс → доступ` со всеми операциями, включая неудачные, с причиной. Типичные ситуации, которые он обязан объяснять:

- заказ оплачен, но у покупателя нет учётной записи;
- товар не связан ни с одним курсом;
- статус заказа не входит в список «выдающих доступ»;
- пользователь уже имеет активное основание;
- курс удалён или снят с публикации.

Для каждой ситуации доступно ручное действие: выдать доступ, привязать к другому пользователю, повторить обработку заказа.

## 5. Тесты

### 5.1. Типы вопросов

Один вариант · несколько вариантов · верно/неверно · короткий ответ · развёрнутый ответ · соответствие · сортировка · заполнение пропусков · загрузка файла · код.

Автоматически проверяются: один вариант, несколько вариантов, верно/неверно, соответствие, сортировка, заполнение пропусков, короткий ответ (по списку допустимых значений с нормализацией регистра и пробелов). Вручную: развёрнутый ответ, загрузка файла, код.

### 5.2. Настройки теста

Банк вопросов с выборкой N случайных · перемешивание вопросов и вариантов · ограничение времени · число попыток · проходной балл · показ правильных ответов (никогда / после каждой попытки / после исчерпания попыток / после проходного результата) · обязательность для завершения курса.

### 5.3. Попытки

**Каждая попытка неизменяема.** Она фиксирует версию теста и снимок каждого вопроса с правилами оценивания на момент прохождения — последующее изменение вопроса не переписывает историю.

**Зачёт результата:** по умолчанию засчитывается **лучшая** попытка. Настраивается: первая, последняя, лучшая, среднее.

**Худшая повторная попытка не отменяет уже пройденный тест.** Если ученик прошёл тест и решил улучшить результат, неудача не лишает его доступа к следующим элементам.

### 5.4. Ручная проверка

Вопросы, требующие человека, попадают в очередь преподавателя вместе с домашними работами (§6). Попытка остаётся в состоянии ожидания проверки; ученик видит, что работа отправлена и ожидает оценки, с указанием срока проверки, если он задан.

## 6. Домашние работы и проверка

### 6.1. Сдача

Форматы: текст · файл · ссылка · фото · видео · аудио · код. Допустимые форматы, лимиты размера и количества задаются в задании.

Черновик сохраняется автоматически и не виден проверяющему до отправки.

### 6.2. Жизненный цикл

```
Черновик → Отправлена → На проверке → ┬→ Принята
                                      ├→ Отклонена
                                      └→ Возвращена → Отправлена (следующая попытка)
```

**Каждая отправка — отдельная неизменяемая попытка.** Работа как сущность хранит текущий статус и номер актуальной попытки; история всех попыток и всех отзывов доступна обеим сторонам.

### 6.3. Назначение проверяющего

Порядок разрешения, сверху вниз:

1. Явно назначенный проверяющий для этого ученика или этой работы.
2. Активные кураторы группы ученика (по приоритету).
3. Преподаватели курса.
4. Очередь «Без проверяющего» — видна администратору с явным предупреждением.

Проверяющий может взять работу в работу (`claim`), освободить её и переназначить другому при наличии права.

### 6.4. Дедлайны

Задаются: фиксированной датой · числом дней от открытия элемента · датой окончания потока. Настраивается поведение при просрочке: приём закрыт · приём открыт со снижением балла · приём открыт без последствий.

Напоминания: ученику — перед дедлайном и после просрочки; преподавателю — о работах, ожидающих проверки дольше заданного срока.

### 6.5. Рабочее место проверяющего

Отдельная страница на фронтенде — не админка WordPress.

Один экран содержит: очередь непроверенных работ с фильтрами (курс, задание, группа, ученик, статус, срок ожидания) · текст задания · материал урока, к которому оно относится · ответ ученика · критерии рубрики · историю предыдущих попыток и отзывов по этой работе · поле отзыва · оценку по критериям · кнопки «Принять», «Вернуть на доработку», «Отклонить».

Массовые действия: назначить проверяющего, перенести дедлайн, отправить напоминание.

Показатели преподавателя: сколько работ ждёт, среднее время проверки, сколько просрочено.

### 6.6. Рубрики

Рубрика привязана к заданию и версионируется. Содержит: критерии с весами · признаки уровней «выполнено / частично / не выполнено» · список типовых ошибок с готовыми формулировками замечаний · примеры одобренных отзывов · указание, что не оценивать.

Изменение рубрики создаёт новую версию; уже выставленные оценки продолжают ссылаться на прежнюю.

Рубрика необязательна: без неё проверка работает как обычная ручная, но ИИ-черновик недоступен.

## 7. ИИ-помощник

### 7.1. Принцип

**ИИ никогда не принимает окончательного решения.** Он готовит редактируемый черновик, решение принимает человек. Автоматическое выставление итоговой оценки, автоматический допуск и недопуск ученика в первой версии отсутствуют полностью.

**Отказ ИИ не останавливает LMS.** При недоступности провайдера, исчерпании лимита или отключённом модуле проверка работает как обычная ручная, без ошибок и предупреждений на стороне ученика.

### 7.2. Функции

| Функция | Что делает |
|---|---|
| Черновик отзыва | По заданию, рубрике и ответу готовит развёрнутую обратную связь с привязкой замечаний к фрагментам ответа и предложенным баллом отдельным полем |
| Помощь с критериями | Предлагает рубрику по материалу урока и по ранее написанным отзывам преподавателя |
| Генерация вопросов | Предлагает вопросы теста по материалу урока |
| Объяснение ошибки | Объясняет ученику, в чём ошибка, **не выдавая готового ответа** |
| Конспект урока | Краткое содержание и опорные тезисы |
| Поиск застрявших | Находит учеников, систематически не проходящих определённый элемент |

### 7.3. Рубрики, созданные ИИ

Обязательный порядок:

1. ИИ предлагает рубрику.
2. Преподаватель редактирует и **явно утверждает** её.
3. Рубрика фиксируется за конкретной версией задания.
4. Только после этого становятся доступны черновики отзывов.

**Автоматическое применение неутверждённой рубрики запрещено.**

### 7.4. Повторная генерация

Преподаватель может осознанно перегенерировать черновик — с другой формулировкой запроса, другой моделью или после правки рубрики. Каждая генерация нумеруется и учитывается отдельно. Случайное дублирование исключено технически (часть 1, §3.11).

Ограничения: лимит генераций на одну работу и общий лимит расходов школы за период, с предупреждением при приближении.

### 7.5. Провайдеры

Единый интерфейс. Школа выбирает провайдера и вводит свой ключ. Поддерживаются: YandexGPT, GigaChat, OpenAI при официальной доступности в юрисдикции школы, совместимые по протоколу и локально размещённые модели.

**Средства обхода региональных ограничений не поставляются и не рекомендуются.**

### 7.6. Данные, передаваемые модели

**Передаётся:** необходимые фрагменты материала урока · текст задания · версия рубрики · ответ ученика · настройки тона и объёма отзыва · до трёх одобренных примеров отзывов.

**Не передаётся:** имя, фамилия, отчество · адрес электронной почты · телефон · IP-адрес · идентификатор пользователя · номер заказа · название школы и курса, если оно не требуется по существу задания.

Отправка оригинальных файлов работ (изображений, документов) включается **отдельным согласием**, отдельно от текстовых ответов.

Оговорка, которая доводится до школы прямо в интерфейсе: ученик может написать свои персональные данные внутри самого ответа, поэтому полное обезличивание не гарантируется. Очевидные фрагменты, похожие на контакты, подсвечиваются преподавателю **без автоматической замены** — вырезанный фрагмент может оказаться частью ответа.

### 7.7. Согласие администратора

Функции ИИ выключены по умолчанию. Включение требует явного подтверждения администратором.

> Включая интеграцию с выбранным ИИ-провайдером, я подтверждаю, что уполномочен действовать от имени организации, ознакомился с условиями и политикой обработки данных провайдера, определил правовое основание обработки и разрешаю передавать выбранные категории данных для подготовки ИИ-черновиков.

**Текст подлежит юридической проверке до выпуска.** Факт подтверждения, дата, пользователь и выбранные категории данных фиксируются в журнале аудита.

## 8. Геймификация

### 8.1. Механики первой версии

Опыт · уровни · серии дней обучения · достижения с условиями · открытие бонусных уроков · индивидуальные, командные и потоковые цели · необязательный рейтинг.

### 8.2. Правила начисления опыта

| Событие | Опыт |
|---|---|
| Завершение урока | Да, один раз за элемент в рамках цикла обучения |
| Прохождение теста | Да, один раз при первом достижении проходного балла |
| **Отправка работы** | **Нет** |
| **Повторная отправка работы** | **Нет** |
| **Принятие работы** | Да, **один раз за работу**, независимо от числа попыток |
| Бонус за принятие с первой попытки | Да, разовый, настраиваемый |
| Бонус за сдачу до дедлайна | Да, разовый, настраиваемый |
| Завершение курса | Да, один раз за цикл |

Начисление за отправку создавало бы прямой стимул отправлять пустые работы. Начисление за каждую попытку — стимул намеренно получать возврат. Обе дыры закрыты правилом «опыт за результат, а не за действие».

### 8.3. Серии дней

Серия продлевается за день, в который ученик совершил учебное действие (завершил урок, сдал тест или работу). Просто вход на сайт серию не продлевает.

Календарные границы дня считаются в часовом поясе, выбранном в настройках — школы или пользователя. Предусмотрена «заморозка серии» на заданное число дней (болезнь, отпуск).

### 8.4. Достижения

Условия строятся из событий: число завершённых уроков, курсов, принятых работ, длина серии, результат теста, скорость прохождения, помощь другим ученикам. Достижение выдаётся один раз и не отзывается автоматически.

### 8.5. Защита от накрутки

Опыт начисляется от свершившегося события, а не от нажатия. Повторное событие того же типа по тому же объекту в рамках цикла опыта не даёт. Отмена действия (например, отмена завершения урока) списывает ранее начисленный опыт отдельной записью реестра, а не удалением исходной.

### 8.6. Рейтинги

Выключены по умолчанию. Настраивается: в пределах группы, курса или всей школы; участие ученика в рейтинге может быть добровольным.

## 9. Уведомления

### 9.1. Каналы

Электронная почта · Telegram · внутренние сообщения в кабинете · объявления курса.

### 9.2. События

Зачисление и открытие доступа · открытие нового элемента по капельной выдаче · приближение и наступление дедлайна · получение отзыва на работу · возврат работы на доработку · результат теста · выдача сертификата · новое объявление · истечение доступа и приближение к нему · для преподавателя — новая работа в очереди и просроченные проверки.

### 9.3. Правила

Каждое уведомление имеет шаблон, редактируемый администратором, с подстановками. Получатель настраивается по роли. Задержка отправки настраивается для каждого события.

Ученик управляет своими уведомлениями в кабинете: канал и типы событий. Отказ от служебных уведомлений (открытие доступа, отзыв на работу) не предусмотрен — они относятся к сути услуги.

**Дедупликация обязательна:** повторная доставка одного и того же события не порождает второго сообщения.

### 9.4. Telegram

Школа подключает своего бота. Ученик привязывает аккаунт разово из кабинета. Отвязка доступна ученику в любой момент. При недоступности Telegram уведомление уходит запасным каналом, если он настроен.

## 10. Сертификаты

### 10.1. Условия выдачи

Сертификат выдаётся после выполнения **всех обязательных элементов курса** и завершения всех обязательных проверок. Дополнительно настраиваются: минимальный итоговый балл, обязательное принятие определённых работ, ручное подтверждение преподавателем.

### 10.2. Поведение

- **Нормальное истечение доступа сертификат не отзывает.**
- Возврат средств после выдачи сертификата **не отзывает его автоматически** — операция попадает на ручную проверку администратору.
- Отзыв возможен вручную с указанием причины; отозванный сертификат перестаёт проходить публичную проверку.
- Перевыпуск (исправление имени, изменение шаблона) создаёт новый документ с новым серийным номером; прежний помечается заменённым.
- Сертификат может иметь срок действия, если это задано в шаблоне.

### 10.3. Проверка подлинности

Публичная страница по серийному номеру или ссылке показывает: имя владельца в том виде, в каком оно на документе, название курса, дату выдачи, статус (действителен, отозван, истёк). Никаких других персональных данных страница не раскрывает.

### 10.4. Конструктор

Шаблон собирается визуально: фон, поля с подстановками (имя, курс, дата, номер, подпись, печать, результат), QR-код на страницу проверки. Генерация — PDF, фоновой задачей.

## 11. Отчёты

### 11.1. Разрезы

### 11.2. Показатели

Только свои курсы и свои группы. Полная картина по школе — только при наличии соответствующего права.

## 13. Импорт

### 13.1. Уровни

Перенос выполняется по уровням, каждый следующий требует предыдущего:

1. **Контент** — курсы, разделы, уроки, вложения.
2. **Оценивание** — тесты, вопросы, задания, рубрики.
3. **Пользователи и зачисления** — учётные записи, права доступа, потоки.
4. **История** — прогресс, попытки, сданные работы, отзывы.

Первые два уровня применимы к незапущенному курсу, при переносе между потоками и при копировании библиотеки уроков. Четвёртый уровень необходим для действующей школы с активным потоком.

### 13.2. Источники

LifterLMS · Tutor LMS · LearnDash. Для каждого — своя карта соответствия сущностей, публикуемая в документации.

### 13.3. Процесс

Предварительный анализ показывает: что будет перенесено, что не имеет соответствия, что потребует ручного решения. Импорт выполняется пакетами в фоне, с журналом и возможностью остановки. Повторный запуск не создаёт дублей.

Исходные данные не изменяются и не удаляются — обратный переход остаётся возможным.

## 16. Открытые вопросы, требующие решения до выпуска

1. Юридическая проверка текста согласия на передачу данных ИИ-провайдеру (§7.7).

5. Поведение при удалении курса, на который существуют выданные сертификаты и незакрытые основания доступа.
