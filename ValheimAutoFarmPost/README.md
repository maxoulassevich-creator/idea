# AutoFarmPost — фермерский столб для Valheim

Столб, который сам собирает урожай вокруг себя и сам сажает семена заново.
Цель — Valheim **1.0.12**, BepInEx 5 + [Jotunn](https://valheim.thunderstore.io/package/ValheimModding/Jotunn/).

**Инструкция по установке для новичка — в файле [`УСТАНОВКА.md`](УСТАНОВКА.md).**

---

## Что он делает

* Новый строительный элемент: **молоток → «Разное» → «Фермерский столб»** (10 дерева + 5 камня, нужен верстак).
* Внутри столба — сундук на 32 ячейки, поделённый пополам:
  * **верхние 2 ряда (16 ячеек)** — семена, которые столб сажает;
  * **нижние 2 ряда (16 ячеек)** — сюда складывается собранный урожай.
* Раз в несколько секунд столб:
  1. собирает вокруг себя всё созревшее (овощи, ягоды, семена);
  2. раскладывает собранное по двум блокам (см. «Куда попадает собранное»);
  3. сажает на освободившееся место новое семя из верхних рядов;
  4. досеивает пустую вспаханную землю в радиусе посадки.
* Работает **только с овощами и ягодами**. Деревья, цветы, грибы, кремень и прочее не трогает.
* **Работает с сундуками вокруг**: забирает семена, складывает урожай — обслуживать руками не нужно.
* **Пугало**: существа не могут повредить растения в радиусе столба.
* **Мифический плод**: редкая находка при сборе, даёт 20-минутный «Дар ворона» — лучший бафф в игре.
* Если нижние ряды заполнены — сбор останавливается, растения остаются в поле (ничего не теряется).

### Куда попадает собранное

В Valheim цикл двойной: из семян вырастает овощ, а из овоща — семенное растение, дающее семена.
Столб поддерживает этот цикл сам:

| Что собрано | Куда идёт |
|---|---|
| семена (морковные, репные, луковые…) | **всё** в верхний блок — они нужны только для посадки |
| овощи и ягоды, которые можно посадить | **половина** в верхний блок (чтобы вырастить из них семена), половина в нижний |
| всё остальное (например, ягоды в ваниле, где кусты не сажаются) | **всё** в нижний блок |

Долю задаёт `SeedShare` (по умолчанию 0.5). Большинство растений даёт один предмет за сбор,
поэтому точную половину за один раз не отдать — остаток переносится на следующий сбор,
и за несколько циклов соотношение выходит ровным (1 вверх, 1 вниз, 1 вверх…).
Если своя половина заполнена, излишек уходит в другую; сбор останавливается только когда
заполнены обе.

### Что именно считается «овощем» и «ягодой»

Списки не зашиты в код, а строятся из данных самой игры при запуске:

* **овощи/посевы** — всё, что вырастает из саженца (`Plant`) и является собираемым (`Pickable`):
  морковь, репа, лук, ячмень, лён, семенные версии, грибы Мистлендса и любые новые культуры,
  которые появятся в игре или в других модах;
* **ягоды** — кусты, роняющие предмет с «berry/berr» в названии: малина, черника, морошка и т. п.
  Ягодные кусты никогда не «пересаживаются» — они отрастают сами, столб просто снимает урожай.

Что-то можно добавить или убрать вручную через `ExtraPrefabs` / `IgnoredPrefabs` в настройках.

## Настройки

Файл `BepInEx\config\com.oulassevich.autofarmpost.cfg`
(или TMM → Installed → AutoFarmPost → **Config editor**).

| Секция | Параметр | По умолчанию | Описание |
|---|---|---|---|
| General | `TickInterval` | 5 | период проверки поля, сек (1–60) |
| General | `MaxHarvestPerTick` | 10 | максимум растений за один цикл |
| General | `MaxPlantPerTick` | 5 | максимум посадок за один цикл |
| Range | `HarvestRadius` | 8 | радиус сбора, м (1–32) |
| Range | `PlantRadius` | 8 | радиус посадки, м (1–32) |
| Range | `PlantSpacing` | 1 | шаг сетки при засеве пустой земли (0.5–4) |
| Filter | `HarvestCrops` | true | собирать посевы |
| Filter | `HarvestBerries` | true | собирать ягодные кусты |
| Filter | `Replant` | true | сажать заново на месте собранного |
| Filter | `PlantOnEmptyGround` | true | засеивать свободную вспаханную землю |
| Filter | `RequireCultivatedGround` | true | сажать только на вспаханную землю |
| Filter | `SeedShare` | 0.5 | какая доля собранных овощей и ягод уходит в верхний блок под посадку (0 — всё в урожай, 1 — всё в семена) |
| Filter | `SeedsToSeedRows` | true | собранные семена всегда уходят в верхний блок |
| Filter | `ExtraPrefabs` | — | что ещё собирать, через запятую (`Pickable_Mushroom,...`) |
| Range | `PlantPattern` | Hex | укладка посадки: `Hex` (плотнее на ~15%) или `Square` |
| Chests | `UseChests` | true | работать с сундуками вокруг |
| Chests | `ChestRadius` | 8 | радиус поиска сундуков, м |
| Chests | `PullSeeds` / `PushHarvest` | true | забирать семена / складывать урожай |
| Chests | `PushThreshold` | 50 | с какой заполненности урожайного блока начинать вывоз, % |
| Chests | `SeedStock` | 50 | сколько семян каждого вида держать в верхнем блоке |
| Chests | `PullOnlySeeds` | false | брать из сундуков только семена, но не овощи |
| Protection | `Scarecrow` | true | защита растений от существ |
| Protection | `ScarecrowRadius` | 10 | радиус защиты, м |
| Mythic fruit | `Chance` | 5 | шанс находки на растение, % |
| Mythic fruit | `BuffSeconds` | 1200 | длительность «Дара ворона», сек |
| Mythic fruit | `Health` / `Stamina` / `Eitr` | 130 / 130 / 70 | показатели еды |
| Interface | `LivingRaven` | true | живой ворон и свечение глаз ночью |
| Filter | `IgnoredPrefabs` | — | что не трогать, через запятую |
| Container | `SeedRows` / `OutputRows` | 2 / 2 | ряды под семена и урожай (нужен перезапуск игры) |
| Interface | `SplitView` | true | показывать сундук двумя отдельными блоками (семена / урожай) |
| Interface | `ShowHoverStatus` | true | статус в подсказке при наведении |

Игровые параметры помечены как admin-only: на выделенном сервере значения раздаются клиентам.

## Как это устроено

| Файл | Ответственность |
|---|---|
| `Plugin.cs` | точка входа, патчи, конфиг |
| `ModConfig.cs` | все настройки |
| `FarmPostPiece.cs` | создание префаба: инвентарь сундука + логика + своя модель, регистрация в молотке, локализация (RU/EN) |
| `RavenPostMesh.cs` | процедурная модель: колонна, шея, череп, клюв, глаза, надбровные дуги |
| `MeshBuilder.cs` | примитивы геометрии (сечения, трубы, крышки, сферы) и кривые |
| `MythicFruit.cs`, `MythicFruitMesh.cs` | мифический плод: предмет, статус-эффект, модель |
| `ContainerRegistry.cs`, `FarmPostRegistry.cs` | быстрые списки сундуков и столбов |
| `PerchedRaven.cs` | живой ворон на столбе и свечение глаз ночью |
| `IconRenderer.cs` | рендер иконок с готовых префабов |
| `FarmPost.cs` | сам цикл: сбор → пересадка → досев, проверка земли и свободного места |
| `FarmData.cs` | карты «семя → саженец → урожай», определение овощей и ягод |
| `InventoryUtils.cs` | работа с отдельными зонами сундука (верх/низ) |
| `PickableUtil.cs` | «срыв» растения без выпадения вещей на землю |
| `PickableRegistry.cs` | быстрый список загруженных растений (без сканирования сцены) |
| `Patches.cs` | регистрация растений + текст подсказки |
| `FarmPostUi.cs` | разделение окна сундука на два блока по 16 ячеек |

Важные решения:

* **Никаких ассет-бандлов.** Префаб собирается в рантайме: за основу берётся `wood_pole2`
  (ради `Piece`/`WearNTear`/сети), а геометрия заменяется собственной — круглая резная
  колонна с головой ворона, которая строится кодом в `RavenPostMesh.cs` (≈3000 треугольников).
  Материал берётся у исходного префаба, поэтому дерево выглядит как вальхеймовское, и
  ни Unity Editor, ни ассет-бандл не нужны.
* **Считает только владелец объекта** (`ZNetView.IsOwner`), поэтому в мультиплеере
  урожай не удваивается.
* **Сначала проверка места в сундуке, потом сбор** — урожай не может пропасть.
* Ягодные кусты помечаются собранными через ZDO (как в игре) и нормально отрастают,
  однолетние посевы удаляются из мира.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Install
```

Скрипт находит игру, копирует `BepInEx.dll`, `0Harmony.dll` и `Jotunn.dll` из вашего профиля
модов в `libs\`, собирает `dist\AutoFarmPost.dll`, делает пакет
`dist\AutoFarmPost-1.1.0.zip` для «Import local mod», а с ключом `-Install` ещё и кладёт мод
в профиль.

Вручную:

```powershell
dotnet build src\AutoFarmPost\AutoFarmPost.csproj -c Release -p:ValheimDir="C:\...\Valheim"
```

Зависимости:

* сборки игры — из вашей папки с Valheim (`valheim_Data\Managed`);
* `BepInEx.dll`, `0Harmony.dll`, `Jotunn.dll` — из папки `libs\` (их туда кладёт `build.ps1`);
* из NuGet тянется единственный пакет `Microsoft.NETFramework.ReferenceAssemblies` —
  он нужен, чтобы собирать под .NET Framework 4.7.2 без Visual Studio.

Публицизация сборок не используется: код обходится публичным API игры, а немногие приватные
члены (`Pickable.SetPicked`, поля `InventoryGui`, `Container.Save`) берутся через рефлексию
и при их отсутствии просто отключают соответствующую мелочь.

### Если сборка не проходит

Код написан под публичный API Valheim/Jotunn, но собрать его против реальных сборок именно
версии 1.0.12 я не мог — у меня нет файлов игры. Ошибки вида
`CS1061: 'X' does not contain a definition for 'Y'` чинятся точечно:

| Что может отвалиться | Файл | Как чинить |
|---|---|---|
| `libs\...dll не найдены` | — | запустить `build.ps1`, он копирует их из профиля модов |
| `zdo.Set(hash, true)` / `GetBool` | `PickableUtil.cs` | подобрать существующую перегрузку `ZDO.Set` |
| `inv.AddItem(item, amount, x, y)` | `InventoryUtils.cs` | сверить сигнатуру `Inventory.AddItem` |
| `Heightmap.FindHeightmap/IsCultivated/FindBiome` | `FarmPost.cs` | убрать проверку земли или заменить актуальным методом |
| `WearNTear.m_noRoofWear` | `FarmPostPiece.cs` | удалить метод `SetupWear` |
| `PieceConfig` / `CustomPiece` | `FarmPostPiece.cs` | сверить с документацией вашей версии Jotunn |

Всё остальное — обычный C#, изолированный от игры.

## Ограничения

* Столб работает, пока рядом находится игрок: Valheim не симулирует незагруженные области
  (печки и плавильни ведут себя так же).
* Пересадка идёт ровно в ту точку, где стояло собранное растение, поэтому поле не «расползается».
* Мод меняет содержимое мира (добавляет постройку) — при удалении мода построенные
  столбы пропадут вместе с содержимым.
* В мультиплеере мод нужен всем участникам и серверу (`EveryoneMustHaveMod`).
