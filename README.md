# RELOD Wishlist — исправление рассинхрона избранного (совместимость с WP Rocket)

Три плагина обновлены до версии **1.2.0**:

| Папка | Что это |
|---|---|
| `relod-wishlist/` | ядро: хранилище, AJAX, шорткод страницы избранного |
| `relod-wishlist-shortcodes/` | кнопка на карточке товара + иконка со счётчиком в хедере |
| `relod-wishlist-ue-bridge/` | связка с виджетом Unlimited Elements Woo Product Grid |

Обновлять нужно **все три сразу**: ядро перестало ходить на сервер через
jQuery, и сателлиты слушают его новое событие `relod_wl:changed`.

---

## Почему это ломалось

### 1. Счётчик приезжал из кеша WP Rocket

`[relod_wishlist_header_icon]` печатал число прямо в HTML, а `wp_localize_script`
клал туда же `relodWLSC.count` и `relodWL.ids`. WP Rocket сохранял этот HTML
в кеш и отдавал всем гостям. В шапке висело избранное того, кто первым открыл
страницу, а на странице избранного (её PHP успевал отработать) — своё.
Ровно это и есть «в счётчике 7, на странице 5».

### 2. Клик «добавить» на закешированной странице приводил к удалению

Фронт присылал команду «переверни состояние», а состояние он брал из
закешированного `relodWL.ids`. Товар в списке уже был → сервер его **удалял**,
хотя пользователь жал «добавить».

### 3. Счётчик мог расти, ничего не сохраняя

```php
// было
$key = self::guest_key();
if ( $key ) { set_transient( ... ); }   // нет куки → тихо ничего не делаем
```

`ajax_toggle()` при этом всё равно отвечал `success` и `count => count($ids)`.
Гостевая кука ставилась на `init`, но на закешированной странице PHP не
запускается вообще, и `Set-Cookie` в кеш не попадает. Итог: счётчик +1,
в избранном пусто.

### 4. Гонка при двух быстрых кликах

`ajax_toggle()` читал массив, менял его и записывал целиком. Два параллельных
запроса читали одно и то же состояние — одно из добавлений терялось.

### 5. Гостевые списки жили в транзиентах

При Redis/Memcached транзиенты вытесняются по памяти, а «Очистить кеш» может
сбросить объектный кеш целиком. Избранное просто исчезало.

### 6. Nonce протухал вместе с кешем

Страница из кеша живёт сутками, `nonce` — 12 часов. `check_ajax_referer()`
отвечал `-1` и обрывал запрос, JS молча откатывал кнопку — «иногда не работает».

### 7. «Delay JavaScript execution» съедал первый клик

WP Rocket откладывал jquery-core и `relod-wishlist.js` до первого
взаимодействия. Обработчик к моменту нажатия ещё не был навешен: первый клик
пропадал, пользователь жал второй раз — уходило два тоггла подряд.

### 8. Удалённые товары оставались в списке

`count(get_ids())` считал все ID, а `wc_get_products()` не возвращал товары,
снятые с публикации или удалённые. Прямая причина «7 против 5», даже без кеша.

## Что сделано

### Хранилище (`relod-wishlist/includes/class-relod-wl-store.php`)

* Гостевые списки переехали из транзиентов в собственную таблицу
  `{prefix}relod_wishlist_guests`. Старые данные мигрируют при первом чтении,
  заброшенные списки чистит ежедневный крон (по умолчанию 90 дней,
  фильтр `relod_wl_guest_ttl_days`).
* Если таблицу создать не удалось, плагин автоматически откатывается на транзиенты.
* `save_ids()` возвращает `bool`. Молчаливых «записал/не записал» больше нет.
* Изменения идут через `mutate()` под `GET_LOCK` — параллельные клики не
  затирают друг друга. Если `GET_LOCK` на хостинге недоступен, работа
  продолжается без блокировки.
* `prune()` убирает из списка товары, которых нет в каталоге, сохраняя порядок
  добавления. Счётчик и страница считают одно и то же.
* Гостевая кука создаётся **только в AJAX-запросах** (`SameSite=Lax`, `HttpOnly`,
  год жизни) — в отрисовке страницы это бессмысленно, её всё равно съест кеш.

### Кеширование (`relod-wishlist/includes/class-relod-wl-cache.php`)

* Персональное состояние не попадает в кешируемый HTML: счётчик и активные
  сердечки подставляет JS. Страницы каталога, товара и хедер по-прежнему
  кешируются полностью — производительность не страдает.
* Признак «кеш активен» — константа `WP_CACHE` или известный плагин
  кеширования. Если сайт кешируется только внешним слоем (Varnish, CDN)
  без плагина, включите режим явно:
  `add_filter( 'relod_wl_page_cache_active', '__return_true' );`
  Без этого на таком сайте состояние отдаётся сразу в HTML — быстрее,
  но внешний кеш может показать его другому посетителю.
* Страница избранного (шорткод или грид UE) помечается `DONOTCACHEPAGE` +
  `do_rocket_generate_caching_files = false` прямо во время рендера, а её URI
  дополнительно уходит в `rocket_cache_reject_uri`.
* Скрипты плагина исключены из `rocket_delay_js_exclusions`,
  `rocket_exclude_defer_js`, `rocket_exclude_js` и аналогов LiteSpeed;
  `defer`/`async` снимаются в `script_loader_tag`.
* При активации и обновлении кеш страниц сбрасывается: старые копии содержат
  чужой счётчик.

### AJAX (`relod-wishlist/includes/class-relod-wl-ajax.php`)

* `relod_wl_state` — новая точка гидрации: отдаёт реальный список, счётчик и
  свежий nonce. Не кешируется (`no-store`, `Vary: Cookie`).
* `relod_wl_toggle` принимает явную операцию `add` / `remove` (`toggle` оставлен
  для совместимости). Операция идемпотентна: повторный `add` не удаляет товар.
* Протухший nonce отдаёт JSON с кодом `invalid_nonce` и свежим nonce вместо
  `die('-1')`. Фронт повторяет запрос один раз.
* Неудачная запись — это `success:false`, а не `success` с выросшим счётчиком.
* `relod_wl_page` отдаёт актуальную разметку грида, если страница всё-таки
  приехала из кеша.

### Фронтенд (`relod-wishlist/assets/relod-wishlist.js`)

* Переписан без jQuery — оптимизаторы больше не могут отложить обработчик.
* Инлайн-перехватчик в `<head>` ловит клики до загрузки основного скрипта и
  складывает их в очередь; скрипт разбирает её при старте. Первый клик не теряется.
* Гидрация состояния на каждой загрузке (и при возврате «назад» из bfcache),
  но только если на странице реально есть кнопки, счётчик или грид избранного.
* Страница избранного сверяется со списком и перерисовывается с сервера при
  расхождении.
* Публичный API: `window.RelodWL.getIds() / getCount() / has() / add() / remove() / refresh()`
  и событие `relod_wl:changed` на `document`.

## Установка

1. Заменить три папки плагинов целиком (или загрузить ZIP через
   «Плагины → Добавить новый → Загрузить плагин» с перезаписью).
2. Открыть «Плагины» — таблица гостевых списков создастся сама, кеш страниц
   сбросится автоматически.
3. Проверить: WP Rocket → «Очистить кеш» (на всякий случай).

Никаких ручных исключений в настройках WP Rocket добавлять не нужно.

### Как проверить, что починилось

1. В приватном окне добавить 2–3 товара в избранное — счётчик и страница
   избранного должны совпадать.
2. Открыть каталог, обновить страницу (она отдаётся из кеша) — сердечки
   на уже добавленных товарах должны загореться, счётчик показать верное число.
3. Снять товар с публикации в админке и обновить страницу избранного —
   счётчик уменьшится вместе со списком, а не разойдётся с ним.
4. WP Rocket → включить «Delay JavaScript execution» → первый клик по сердечку
   должен срабатывать.

## Точки расширения

| Фильтр / хук | Назначение |
|---|---|
| `relod_wl_guest_ttl_days` | срок хранения гостевого списка (по умолчанию 90 дней) |
| `relod_wl_guest_cookie_ttl` | срок жизни гостевой куки (по умолчанию год) |
| `relod_wl_prune_query_args` | аргументы запроса, проверяющего существование товаров |
| `relod_wl_render_personal_state` | принудительно включить/выключить серверный рендер состояния |
| `relod_wl_page_cache_active` | сообщить плагину, что перед сайтом стоит кеш (Varnish, CDN) |
| `relod_wl_image_size` | размер картинки в карточке на странице избранного |
| `relod_wl_changed` (action) | срабатывает после успешного изменения списка |
